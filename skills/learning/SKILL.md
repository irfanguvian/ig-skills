# /learning

Project memory in `<repo>/.learning/`, local only (`.learning/.gitignore` = `*`). Never `git add` it or name it in commits.
Helper CLI, use it: `bash ~/.claude/skills/learning/bin/learn.sh {find <terms>|build|status|onboard steps below}`.

## Used only 3 times per task
1. **First run on a repo with no `.learning/`** → onboard (below).
2. **Plan:** one `learn.sh find <terms>` (max 5 words). Read every `DEC` line it returns; open only the docs it names, max 3. A miss → fall back to Grep, never conclude absence.
3. **Verdict:** save (below) automatically, then list the new facts under "Learned" in the report.
No hooks. No search per Grep. Do not reload this skill mid-task.

## Layout
```
.learning/
  INDEX.md        generated by learn.sh build; one row per note
  CODEBASE.md     what the app is: business process, actors, flows, stack, invariants
  modules/<name>.md  one per module: purpose, entry points, key files, deps, gotchas
  DECISIONS.md    append-only, one line per decision
  SESSIONS.md     newest first, one block per session
  specs/          test-engineer-irfan specs
```

## find output
`INDEX` rows, `DOC <path> (n hits)`, `DEC <line>` (decisions), `SES <header>`, `NODE` (graph). Prints nothing on no match. Terms under 5 chars match whole words; 5+ chars match word prefixes.

## save — at the verdict
1. Next ids: `grep -c '^## S-' .learning/SESSIONS.md`, `grep -c '^- D-' .learning/DECISIONS.md`.
2. Prepend one block after `# Sessions` (same session id already on top → update it in place):
```
## S-0007 2026-08-23 add-refund-endpoint sid:a1b2c3d4
verdict: shipped — refund POST live
work: refund service + controller [[billing]]; integration test
decisions: D-0012
next: webhook retry backoff
```
3. One line per non-obvious choice in DECISIONS.md, with the rejected option:
   `- D-0012 2026-08-23 [[billing]] refunds idempotent by Idempotency-Key; rejected: dedupe by amount+time (race)`
4. A touched module changed behaviour, structure or contract → edit its doc in place. Nothing structural → touch nothing.
5. `learn.sh build`. Parallel sessions share one DB: re-read before writing, never overwrite another session's block.

## onboard — first run only
1. Read README / CLAUDE.md, find module boundaries. More than 12 → group by business domain.
2. Per module, one read-only helper (2–4 in parallel) returns: purpose, entry points, key files, deps, gotchas, with file:line, max 40 lines.
3. Write `.gitignore` (`*`), `CODEBASE.md`, `modules/*.md`, `DECISIONS.md` (seed with visible choices, tag `(inferred)`), `SESSIONS.md` (S-0001 onboard block).
4. `learn.sh build` then `learn.sh status`: zero `problem:` lines.
5. `learn.sh hooks install` (git worktree seed only, no Claude hooks).

## Rules
- Worktrees read and write the main checkout's `.learning/` (`learn.sh` resolves it). Never `mkdir .learning` in a worktree.
- Code wins over a doc; fix the doc in the same session.
- Module docs are rewritten in place. Only SESSIONS and DECISIONS grow.
- Other commands (`query`, `module`, `migrate`, `vault`, `doctor`, `fix`, `stats`) still work; see `README.md` in this folder.
